# API reference

The API serves JSON. `/health` is public. When `api.token` is configured, every `/v1/*` route requires `Authorization: Bearer <token>` and otherwise returns `401 {"error":"unauthorized"}`. The three management routes always require a configured token and an exact bearer match. Examples use `ARGUS_URL=http://127.0.0.1:8788` and `ARGUS_API_TOKEN`.

## `GET /health`

Authentication: none. Request: no body. Success: `200` with `{ "status": "ok", "version": 1, "role": "all|api|scheduler|worker|processor", "intelligence": true }`. The route has no application-defined deterministic error response.

```bash
curl "$ARGUS_URL/health"
```

## `GET /v1/records`

Authentication: bearer token when configured. Request: no body. Repeat `source` (`x`, `telegram`, or `web`) and `target` to select any matching source or target; `q` is a text query. `since` and `until` are parseable ISO-8601 timestamp bounds. `limit` is an integer from 1 to 200 (default 50).

The optional `cursor` is strict: it must be the canonical base64url encoding of exactly `{ "v": 1, "ingestedAt": "<ISO timestamp>", "id": "<non-empty string>" }`. Do not construct a cursor from a record ID alone; pass the returned `nextCursor` unchanged.

Success: `200` with `{ "items": [record], "nextCursor": "...", "summary": "1 record" }`, where `nextCursor` is omitted at the end. A record has required `id`, `source`, `targetId`, `externalId`, `url`, `text`, `raw`, `watchIds`, `contentHash`, and `ingestedAt`; `title`, `author`, `publishedAt`, and `metadata` are optional.

Deterministic errors: `400 {"error":"limit must be an integer from 1 to 200"}`, `400 {"error":"since and until must be ISO-8601 timestamps"}`, or `400 {"error":"invalid records cursor"}`; plus `401` authentication failure.

```bash
curl -H "Authorization: Bearer $ARGUS_API_TOKEN" \
  "$ARGUS_URL/v1/records?source=web&source=telegram&target=public-signals%3Aweb%3Aurl%3Ahttps%253A%252F%252Fexample.com&since=2026-08-01T00%3A00%3A00.000Z&limit=50"
```

## `GET /v1/artifacts`

Authentication: bearer token when configured. Request: no body; optional `kind` filters exact artifact kind and `limit` is an integer from 1 to 200 (default 50).

Success: `200` with `{ "items": [artifact] }`. There is no artifact cursor or `nextCursor`. An artifact has `id`, `recordIds`, `kind`, `content`, `provenance`, and `createdAt`, with optional `provider` and `model`.

Deterministic errors: `400 {"error":"limit must be an integer from 1 to 200"}` and `401` authentication failure.

```bash
curl -H "Authorization: Bearer $ARGUS_API_TOKEN" \
  "$ARGUS_URL/v1/artifacts?kind=summary&limit=20"
```

## `POST /v1/watches/:watchId/ingest`

Authentication: bearer token when configured. Request: no body; `watchId` must name an enabled configured watch. Success: `202 { "queued": 2, "watchId": "public-signals" }`, where `queued` is the number of new immediate jobs.

Deterministic errors: `404 {"error":"watch not found"}` and `401` authentication failure.

```bash
curl -X POST -H "Authorization: Bearer $ARGUS_API_TOKEN" \
  "$ARGUS_URL/v1/watches/public-signals/ingest"
```

## `POST /v1/summaries`

Authentication: bearer token when configured. Request: a JSON object. Its optional `query`, `watchIds`, and `prompt` values are consumed directly: truthy `query` and `watchIds` are passed to the stored-record query, and `prompt` is passed to OpenRouter. This endpoint does not type-validate those values. `limit` defaults to 50 and is the only field with deterministic validation: it must be an integer from 1 through 100. Success: `201` with `{ "id": "...", "content": "...", "model": "...", "generationId": "...", "sources": [{ "index": 1, "recordId": "...", "url": "..." }] }`; `generationId` may be omitted.

The generated summary is also persisted as a `summary` artifact. Deterministic errors: `409 {"error":"intelligence is disabled"}`, `400 {"error":"invalid summary request"}`, `400 {"error":"limit must be an integer from 1 to 100"}`, and `401` authentication failure.

```bash
curl -X POST "$ARGUS_URL/v1/summaries" \
  -H "Authorization: Bearer $ARGUS_API_TOKEN" -H "Content-Type: application/json" \
  --data '{"watchIds":["public-signals"],"limit":25,"prompt":"Summarize changes and cite them."}'
```

## Diagnostic smoke watches

These routes are for the CLI doctor flow. They create a temporary, configured target snapshot with a 15-minute expiry; they are not a general watch-management API.

### `POST /v1/diagnostics/smoke-watches`

Authentication: bearer token when configured. Request: exactly `{ "source": "x|telegram|web", "targetId": "configured-target-id" }`. Success: `202 { "id": "uuid", "targetId": "__argus_doctor:uuid" }`.

Deterministic errors: `400 {"error":"invalid diagnostic watch request"}`, `400 {"error":"configured web diagnostic target is not permitted"}`, `404 {"error":"configured enabled diagnostic target was not found"}`, `409 {"error":"diagnostic watch could not be created"}`, and `401` authentication failure.

```bash
curl -X POST "$ARGUS_URL/v1/diagnostics/smoke-watches" \
  -H "Authorization: Bearer $ARGUS_API_TOKEN" -H "Content-Type: application/json" \
  --data '{"source":"web","targetId":"public-signals:web:url:https%3A%2F%2Fexample.com"}'
```

### `GET /v1/diagnostics/smoke-watches/:id/records`

Authentication: bearer token when configured. Request: no body. Success: `200 { "items": [record] }`, using the record shape from `GET /v1/records`.

Deterministic errors: `404 {"error":"diagnostic watch not found"}` and `401` authentication failure.

```bash
curl -H "Authorization: Bearer $ARGUS_API_TOKEN" \
  "$ARGUS_URL/v1/diagnostics/smoke-watches/0f1d2c3b-4a5b-678c-9d0e-1f2a3b4c5d6e/records"
```

### `DELETE /v1/diagnostics/smoke-watches/:id`

Authentication: bearer token when configured. Request: no body. Success: `204` with an empty body; Argus cancels and removes that temporary diagnostic watch.

Deterministic errors: `404 {"error":"diagnostic watch not found"}` and `401` authentication failure.

```bash
curl -X DELETE -H "Authorization: Bearer $ARGUS_API_TOKEN" \
  "$ARGUS_URL/v1/diagnostics/smoke-watches/0f1d2c3b-4a5b-678c-9d0e-1f2a3b4c5d6e"
```

## Host-wrapper configuration routes

The installed host wrapper uses these three routes to inspect, apply, and verify a configuration reconciliation. They are not a replacement for `argus config validate`, `argus config apply`, or the supported CLI workflow. Their request configuration is the parsed JSON/YAML configuration object, never a document containing unexpanded environment references.

### `POST /v1/management/config/plan`

Authentication: a configured exact bearer token is required. Request: exactly `{ "path": "/absolute/path", "config": { ... } }`; `path` must start with `/`, and `config` must pass `validateConfig`. Success: `200` with `{ "contractVersion": 1, "planId": "sha256", "path": "/absolute/path", "baseContentHash": "sha256", "desiredContentHash": "sha256", "operations": [{ "resource": "applied-config", "action": "create|update", "summary": "..." }] }`; `baseContentHash` is omitted on first apply. Preserve the returned `path` verbatim in the plan object: it is part of the plan identity used by both apply and verify.

Deterministic errors: `400 {"error":"invalid configuration plan request"}` and `401 {"error":"unauthorized"}`.

```bash
curl -X POST "$ARGUS_URL/v1/management/config/plan" \
  -H "Authorization: Bearer $ARGUS_API_TOKEN" -H "Content-Type: application/json" \
  --data '{"path":"/opt/argus/argus.yaml","config":{"version":1,"storage":{"adapter":"sqlite","url":"./data/argus.db"},"sources":{},"watches":[]}}'
```

### `POST /v1/management/config/apply`

Authentication: a configured exact bearer token is required. Request: exactly `{ "path": "/absolute/path", "config": { ... }, "inspection": plan }`, where `inspection` is the unchanged successful plan response for the same path and config. Success: `200 { "planId": "sha256", "receipt": { ... } }`.

Deterministic errors: `400 {"error":"invalid configuration apply request"}`, `409 {"error":"configuration plan is stale"}`, and `401 {"error":"unauthorized"}`.

```bash
curl -X POST "$ARGUS_URL/v1/management/config/apply" \
  -H "Authorization: Bearer $ARGUS_API_TOKEN" -H "Content-Type: application/json" \
  --data @apply-request.json
```

`apply-request.json` must contain the original `path`, `config`, and `inspection` from the plan call; preserve `inspection.path` verbatim and make the request `path` match it. Changing the path, any hash, or any operation makes the plan stale.

### `POST /v1/management/config/verify`

Authentication: a configured exact bearer token is required. Request: exactly `{ "inspection": plan }`. Success: `200 { "healthy": true, "planId": "sha256", "status": { "desiredContentHash": "sha256" } }`.

Deterministic errors: `400 {"error":"invalid configuration verify request"}`, `409 {"error":"configuration plan is stale"}`, and `401 {"error":"unauthorized"}`.

```bash
curl -X POST "$ARGUS_URL/v1/management/config/verify" \
  -H "Authorization: Bearer $ARGUS_API_TOKEN" -H "Content-Type: application/json" \
  --data @verify-request.json
```

`verify-request.json` contains `{ "inspection": <the unchanged plan response> }`, including its original `path`; changing that path invalidates the plan identity.
