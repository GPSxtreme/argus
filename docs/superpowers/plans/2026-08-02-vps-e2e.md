# Clean VPS E2E Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Verify an immutable signed release candidate can onboard and operate a clean VPS topology on Ubuntu 24.04 and Debian 13.

**Architecture:** A host-side shell harness resolves the signed candidate’s exact installer and manifest assets, uses a public HTTPS page controlled by the Argus project, and runs the management CLI against `/opt/argus`. The workflow invokes that harness on two Docker rootfs variants. Documentation describes the same supported operations and recovery contracts.

**Tech Stack:** POSIX shell, Docker Compose, GitHub Actions, YAML, Markdown, Node 24/pnpm verification.

## Global Constraints

- Use an explicitly selected immutable signed release tag and exact private asset API URLs.
- The harness must be opt-in through `ARGUS_VPS_E2E=1` and clean its containers, networks, and temporary files.
- Assert onboarding idempotence, doctor/status JSON contracts, controlled Web ingestion, managed SearXNG JSON output, and only host port 8788.
- The workflow matrix must include Ubuntu 24.04 and Debian 13.
- Commit locally only; do not push.
